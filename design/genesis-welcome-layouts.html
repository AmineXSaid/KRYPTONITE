Genesis · Welcome screen · Layout study

When the panel goes wide, Genesis shouldn't float in a puddle of empty margin.

The welcome column is capped at 340 px and centered. In a narrow dock that's right — there's nothing to line up against. But undocked into the editor or on a wide screen, the same cap leaves a big void on each side and the identity reads as lost, not composed. Here are eight ways to spend that width.

source: media/webview/sidebar.css · .welcome current cap: max-width 340px 8 treatments · low → high effort

The situation today

The .welcome block is a single centered axis: mark, wordmark, one line of copy, a Try list, and (when they exist) recent threads — all inside a 340 px measure. It was centered on purpose so a left-aligned mark wouldn't sit against the panel edge with the whole width empty beside it.

That trade is correct at ~320–420 px. Past roughly 560 px the centered cap stops helping and the two dead columns start hurting — which is exactly the wide view in the screenshot.

The goal isn't "stretch everything." It's to make the width feel intended at every dock size.

What I'd actually ship

These aren't mutually exclusive — the strongest plan is layered by effort. Pick a floor, then decide how far up to go.

  • Ship now02 Fluid Measure as the baseline — one clamp() removes the "puddle" feeling everywhere for near-zero risk, and keeps the design the team already committed to.
  • Then layer03 Split above a ~640px breakpoint. It reuses only existing parts (Try + Recent), so there's nothing new to invent and it degrades cleanly to the stack.
  • The bet05 Workspace Dashboard if you want the wide panel to earn its space — greeting the user with branch, dirty files and the open file is the one option that makes width a feature, not a fix.
  • Keep in pocket01 Anchored Center as the guaranteed fallback if any responsive option slips the release.
